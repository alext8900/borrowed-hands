# Protocol v1 test vectors

`vectors.json` is generated by `python3 -I protocol/gen_test_vectors.py` (needs `cryptography`). Regenerate it only
when the protocol version changes; a diff in this file outside a version bump is a bug.

An implementation in any language conforms when it:
1. turns every `canonical[].input_json` into exactly `canonical_hex` (PROTOCOL 2.3: RFC 8785 restricted to ASCII
   `[a-z0-9_]` keys, integers in +-(2^53-1), no floats, valid Unicode);
2. rejects every `reject[].input_json` (parse or canonicalize must fail);
3. with the seed from `keys`, produces `signatures[].signature_b64u` over `signed_bytes_hex` (= context bytes,
   including the trailing NUL, followed by the canonical message), verifies it with the public key, and fails to
   verify `tampered_message_hex`;
4. computes `fingerprints[].fingerprint` (and rejects the `reject` URLs), `keys.*.key_id` and the pairing string.

Ed25519 here is RFC 8032 pure Ed25519, so signatures are deterministic and must match byte for byte.
The seeds are test-only constants. Never use them for a real key.
